# Совместимость зависимостей

Сценарий не содержит `requiredAddons[]` для A4A, CBA или ACE и не переносит их
код внутрь миссии. Клиентская часть A4A не нужна: весь собственный код приходит
с миссией. Маркеры матрицы: `NO_CBA`, `NO_ACE`.

## Матрица

| Сервер | Клиент | Результат |
|---|---|---|
| NO_CBA, NO_ACE | NO_CBA, NO_ACE | Полный количественный Legacy Arsenal и грузовые операции |
| CBA_A3 3.19.0 | CBA_A3 3.19.0, NO_ACE | Настройки CBA плюс Legacy Arsenal |
| CBA_A3 3.19.0 + ACE3 3.21.1 | CBA_A3 3.19.0 + ACE3 3.21.1 | ACE proxy только для полностью бесконечного склада; конечный склад использует Legacy |
| CBA/ACE на сервере | NO_CBA, NO_ACE на клиенте | Клиент использует Legacy; сервер не навязывает ему ACE |
| CBA/ACE на сервере | смешанные клиенты | Каждый клиент выбирает локально доступный адаптер; канонический склад остаётся общим серверным |

ACE3 сам зависит от CBA; сценарий не пытается поддерживать невозможную
конфигурацию ACE без CBA. Игрок без ACE не получает ошибок отсутствующих функций.

## Контракт CBA_A3 3.19.0

Из установленного `cba_settings.pbo` извлечена фактическая
`fnc_addSetting.sqf`. Используемая публичная сигнатура содержит восемь полей:
имя, тип, заголовок, категорию, описание значения, глобальность, callback и
`needRestart`. Адаптер:

- сначала проверяет существование `CBA_fnc_addSetting`;
- регистрируется идемпотентно на каждой машине;
- читает результат из создаваемых CBA глобальных переменных через
  `missionNamespace`;
- не вызывает несуществующую `CBA_fnc_getSetting`;
- при отсутствии CBA читает `A4A\config\settings.sqf`;
- значения по умолчанию для регистрации CBA берёт из того же файла, поэтому
  появление CBA само по себе не меняет политику сценария;
- клиентский признак редактора использует нормализованное значение CBA только
  для видимости UI, но окончательное полномочие всегда повторно проверяет сервер;
- на сервере один раз копирует SteamID, режим редактора, доступ к грузу и
  глобальный порог в закрытую карту до создания реестра арсеналов;
- `0` в CBA сохраняет индивидуальные пороги из `arsenals.sqf`, положительное
  значение заменяет их после перезапуска; для магазинов оно переводится в пул
  патронов через `CfgMagazines.count`.

## Контракт ACE3 3.21.1

Из установленного `ace_arsenal.pbo` сверены реальные сигнатуры:

- `[_proxy, _items, false] call ace_arsenal_fnc_addVirtualItems`;
- `[_proxy, true, false] call ace_arsenal_fnc_removeVirtualItems`;
- `[_proxy, player, false] call ace_arsenal_fnc_openBox`.

Третий параметр везде передаётся явно и запрещает глобальную публикацию.
Постоянный объект арсенала никогда не передаётся в ACE. Создаётся невидимый
`Land_HelipadEmpty_F` через `createVehicleLocal`; состояние хранит отдельно
исходный объект, proxy, nonce и generation. Закрытие проверяет
`ace_arsenal_currentBox`, очищает только свой proxy на следующем кадре и отправляет
коррелированный `A4A_fnc_requestClose`.

`ace_arsenal_fnc_initBox` и `ace_arsenal_fnc_removeBox` не используются. Поэтому
сценарий не ставит постоянное ACE-действие, JIP-запись или глобальную виртуальную
номенклатуру на исходный ящик.

ACE меняет экипировку до поздних UI-событий. Поэтому текущий безопасный контракт
намеренно не имитирует конечный количественный протокол через эти события:
любой конечный остаток открывается в Legacy. Это сохранение целостности, а не
утрата складской функциональности.

## Статус доказательства

Сверка исходных сигнатур, хешей PBO и статических путей выполнена. Запуск UI в
реальной Arma 3 с CBA/ACE, mixed-client и dedicated режимы пока `NOT_RUN`; полный
перечень находится в `VERIFICATION.md`.
