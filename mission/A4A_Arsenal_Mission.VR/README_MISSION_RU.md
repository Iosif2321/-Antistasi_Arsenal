# Количественный арсенал как распакованный сценарий

Метка поставки: `UNPACKED_MISSION`, `NO_PBO`.

Это самостоятельная папка сценария Arma 3. Отдельный клиентский или серверный
мод A4A не требуется: сервер загружает сценарий, а Arma передаёт клиентам его
SQF-код, UI-описания и ресурсы обычным механизмом миссии. Папку не нужно и не
следует упаковывать в PBO.

Сценарий реализует только количественный арсенал и операции с физическим
снаряжением. Подсистема Garage удалена. Техника здесь имеет режим `CARGO_ONLY`:
она может быть только физическим держателем груза, аналогично ящику.
`NO_VEHICLE_STORAGE_OR_SPAWN`: сохранения, виртуального хранения, покупки,
создания и восстановления самой техники нет.

## Быстрый запуск

1. Скопируйте всю папку `A4A_Arsenal_Mission.VR` без изменения внутренней
   структуры в каталог `MPMissions` сервера или локальной установки Arma 3.
2. Для выделенного сервера выберите шаблон миссии в `server.cfg`:

   ```cpp
   class Missions
   {
       class A4A_Quantitative_Arsenal
       {
           template = "A4A_Arsenal_Mission.VR";
           difficulty = "Regular";
       };
   };
   ```

3. Не добавляйте `@Antistasi_Arsenal` в `-mod` или `-serverMod`. Игрокам также
   не нужно устанавливать A4A.
4. CBA_A3 и ACE3 необязательны. Без них используется Legacy-интерфейс. ACE UI
   может появиться только у клиента, который сам загрузил ACE3; конечные
   количественные остатки всё равно открываются через транзакционный Legacy UI.

Эталонная VR-карта содержит два игровых слота `B_Soldier_F` для hosted/two-client
проверок и стандартный ящик `B_supplyCrate_F` с Eden-переменной
`a4a_arsenal_base`.

## Перенос в другую миссию

Минимальный перенос выполняется копированием в корень вашей распакованной
миссии следующих элементов:

- папки `A4A` целиком;
- `initServer.sqf` и `initPlayerLocal.sqf` либо эквивалентных вызовов из них;
- `Stringtable.xml`;
- директив `#include` из `description.ext`.

В Eden назначьте каждому постоянному ящику переменную, а затем добавьте строку
в `A4A\config\arsenals.sqf`:

```sqf
[
    ["a4a_arsenal_base", "Base", 25],
    ["a4a_arsenal_forward", "Forward", 10]
]
```

Поля строки:

1. точное имя Eden-переменной сетевого объекта;
2. уникальный постоянный ID склада (до 64 символов);
3. порог автоматической разблокировки: после накопления указанного числа
   физических экземпляров конечное значение превращается в `-1`; `0` отключает
   автоматическую разблокировку для этого склада.

Объект должен существовать при `initServer.sqf`, иметь сетевой `netId` и быть
доступен всем клиентам. Не создавайте ID из пользовательского ввода. Общие
лимиты, дистанции и список SteamID редакторов находятся в
`A4A\config\settings.sqf`. При наличии CBA часть параметров появляется в
Configure Addons; сервер копирует влияющие на полномочия значения один раз до
регистрации складов.

## Семантика запасов

- `-1` означает бесконечный запас.
- Положительное целое число означает конечный запас.
- Для обычных предметов и оружия единица — один физический экземпляр.
- Для магазинов число — пул оставшихся патронов, а не число магазинов. При
  загрузке ящика сервер создаёт физические магазины с точным остатком патронов.
- Поэтому порог магазина переводится сервером в патроны как
  `порог × CfgMagazines.count`: например, порог `25` для магазина на 30 патронов
  разблокирует его при накоплении 750 патронов.
- Порог применяется сервером после загрузки сохранения, возврата снаряжения,
  внесения груза и сохранения редакторского снимка. Скрытого деления игроков на
  участников и гостей в автономном сценарии нет.
- Каноническое состояние, ревизии, сессии, резервирования и блокировки груза
  находятся в закрытом `localNamespace` сервера.
- Клиентская операция не меняет склад окончательно без серверного подтверждения.

## Ящики и техника

У зарегистрированного арсенала доступны два действия:

- положить всё физическое содержимое объекта под курсором в арсенал;
- загрузить в объект под курсором копию текущего комплекта игрока, списав её из
  арсенала.

Объектом может быть ящик или пустая техника с грузовым объёмом. Сервер проверяет
игрока, дистанцию, регистрацию арсенала, вместимость и локальность объекта.
Операция получает блокировку конкретного держателя, создаёт рекурсивную копию
магазинов с остатками, оружия с обвесом и вложенных рюкзаков, проверяет итоговый
склад и только затем очищает либо дополняет груз. При частичной записи выполняется
точный откат. Действия с занятой техникой отклоняются.

## Сохранение, резервная копия и сброс

Метка процедуры резервирования: `PERSISTENCE_BACKUP`.

Сервер сохраняет каждый склад в своём `profileNamespace` под ключом
`A4A_MissionArsenal_v2_<ID>`, например `A4A_MissionArsenal_v2_Base`. Запись имеет
формат `[2, revision, data]`. Старый ключ `A4A_ArsenalData_<ID>` читается только
для одноразовой миграции; новое состояние сохраняется под ключом v2.

Перед обновлением или ручным сбросом:

1. штатно остановите сервер;
2. сделайте резервную копию фактического файла профиля сервера
   (`*.Arma3Profile`/`*.vars.Arma3Profile`, путь зависит от `-profiles` и `-name`);
3. сохраните копию вне каталога профиля;
4. только после этого меняйте ключи.

Метка процедуры сброса: `PERSISTENCE_RESET`. Для сброса одного склада выполните
на сервере в доверенном локальном контексте и затем перезапустите миссию:

```sqf
profileNamespace setVariable ["A4A_MissionArsenal_v2_Base", nil];
saveProfileNamespace;
```

Не передавайте этот код клиенту через `remoteExec`. После удаления ключа склад
стартует пустым, если нет допустимого старого ключа миграции. Для абсолютно
чистого сброса отдельно удалите соответствующий `A4A_ArsenalData_Base`, также
только после резервного копирования профиля.

## Границы подтверждения

Статические тесты и `CfgConvert` подтверждают структуру, whitelist RPC,
сигнатуры адаптеров и синтаксис конфигураций. Они не доказывают работу движка,
сетевую гонку двух настоящих клиентов, сохранение после реального рестарта или
поведение конкретной сборки модов. Текущий журнал доказательств и обязательные
ручные проверки находятся в `VERIFICATION.md`.
